# 去重算法

## 问题

Apple 健康的 `export.xml` 保存的是**每个来源的原始样本**。同一段时间内：

- Apple Watch 记录了自己数出的步数；
- iPhone 也记录了自己数出的步数（手机在口袋里时两者几乎同时计步）；
- 第三方 App（Keep、小米运动健康等）可能再写一份。

````text
10:00 ────────────── 10:20 ────────────── 11:10
Watch   ├──── 600 步 ────┤├──── 400 步 ────┤
iPhone  ├──── 590 步 ────┤├──── 395 步 ────┤        ├── 500 步 ──┤
````

朴素求和 = 600 + 400 + 590 + 395 + 500 = **2,485 步**，实际约 **1,500 步**（多算了 65%）。

## 方案：时间区间并集 + 设备优先级

1. 同一指标的记录按天分组；
2. 记录按 `(设备优先级降序, 开始时间升序)` 排序；
3. 维护一个已覆盖时间区间集合（有序、已合并）；
4. 每条记录只有**尚未被覆盖的时间比例**才计入：

```text
fraction = 1 - covered_seconds(record) / duration(record)
total   += value * fraction
```

5. 把该记录加入覆盖集合。

对上面的例子：Watch 的两条先覆盖 10:00–10:20，计入 1,000；
iPhone 的两条与已覆盖区间完全重合，计入 0；
iPhone 11:00–11:10 未被覆盖，计入 500。合计 **1,500**。

### 为什么不是「每天取最大值」

手表只戴了半天的日子，最大值会漏掉手机记录的另一半；设备时钟略有漂移时，
「逐分钟取最大」也会在两条记录跨越不同分钟边界时重复计数。

### 为什么不是「逐分钟去重」

最早的实现按分钟桶去重（同一个分钟只保留一个设备的值），在真实数据上仍然偏高：

```text
Watch  10:00–10:10 600        iPhone 10:00–10:10 590   → 同一分钟，去重正确
Watch  10:00–10:30 1,200      iPhone 10:00–10:10 590   → 分钟桶只覆盖了 10 分钟
```

两分钟粒度对齐不上，就会把同一次走路算两遍。区间并集与粒度无关。

## 校验

用系统「健身记录」三环的**每日活动能量**作为独立参照（Apple 在 App 里展示的是
去重后的值）：

| 指标 | 结果 |
|---|---|
| 可对比天数 | 486 |
| 去重值和三环值的中位比值 | **1.000** |
| 偏差 >5 kcal 的天数 | 44（集中在有第三方 App 训练的早期） |

## 优先级

默认 `Watch > iPhone > iPad > Mac > iPod`，其它来源排在最后。可以用
`--priority` 覆盖：

```bash
healthkit-report parse export.xml --priority "iPhone" "Watch"
```

优先级相同的来源（例如两台不同型号的 iPhone）按记录开始时间排序，二者通常
覆盖不同日期，不会互相吞掉。

## 均值类指标

心率、HRV、血氧、呼吸频率等不需要累加。它们的去重规则是：**同一个分钟窗口内
只保留优先级最高的那条样本**，再对当天取均值。这样可以避免第三方 App 在同一
时刻写入的异常值（例如 190 bpm）把均值拉偏。

## 睡眠

睡眠是区间重叠问题，不能简单并集：Apple 会把一夜拆成几十条 Core/Deep/REM 记录。

处理方式：

1. 按「醒来日期」把记录归到一个夜晚；
2. 按来源优先级分组，每组分别累加 Core/Deep/REM/InBed/Awake；
3. 取「睡眠时长最长」的那一组（通常就是手表）。

这样既不会把两个来源的同一夜相加，也不会因为手表只记录了一半而丢掉另一来源
的补充记录。

## 已知偏差

- 若两个设备对同一段活动的计量差异很大（例如手表在跑步机上、手机在包里），
  结果会偏向高优先级设备。
- 设备时钟不同步（偏差 >1 分钟）时，边界处可能有几秒钟重复计入，量级可忽略。
- 没有记录的时间段不会被推断或补齐。
